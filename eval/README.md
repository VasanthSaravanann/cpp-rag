# cpp-rag eval harness

Measures retrieval quality so chunk sizes, `--scales`, `--per-scale`, and model
swaps can be compared with numbers instead of impressions.

```sh
./eval/run --scales 1000:150,300:40          # retrieval metrics
./eval/run --scales 1000:150                 # another configuration
./eval/run --generate --max-tokens 128       # also score generated answers
./eval/run --k 5 --metric dot
```

`eval/run` builds the core tree on demand. It needs `CPP_RAG_BIN` to point at a
llama-enabled `cpp-rag` (default `build/cpp-rag`), plus both GGUF models under
`models/`. Indexes and per-case command logs are kept only when `--keep` is
passed, under `eval/.cache/`.

Each case asks a question over a document, and every retrieved chunk is scored
by matching `expect_substring` (case-insensitive) against the chunk text.
Metrics per case:

- **hit@k** — at least one retrieved chunk contains the substring.
- **MRR** — reciprocal rank of the first matching chunk.
- **answer@k** (`--generate` only) — the generated answer contains the substring.
- **abstain rate** — share of `no_evidence` cases whose answer declines to
  answer (matched by `expect_substring`, a refusal phrase).

`--per-scale N` is applied exactly as the CLI applies it, so quota-driven result
loss shows up in hit@k.

## Provenance: these cases are not a labelled gold set

`cases.json` was drafted mechanically by inspecting `eval/documents/` source
text. **It is unverified scaffolding, not a ground-truth or evaluation gold set**
— no human has adjudicated the answers, no coverage or ambiguity review has
happened, and the documents themselves are generated fixtures. Treat the printed
numbers as a *regression signal for this harness only*:

- Do not promote any configuration to "best" from these scores.
- Do not use them to set operating thresholds.
- Replace `cases.json` with human-labelled cases over real documents before
  making retrieval or generation quality claims.

Exit status is 0 whenever the harness completes; it never gates on metric
values, because there is no approved threshold to gate against.

## Files

| Path | Role |
|---|---|
| `eval/cases.json` | questions, expected substrings, provenance |
| `eval/documents/` | fixture corpus, regenerated by `make_documents.py` |
| `eval/make_documents.py` | deterministic fixture generator |
| `eval/eval.cpp` | metric engine, `cpp_rag_eval` |
| `eval/run` | configure/build/invoke wrapper |
| `eval/.cache/` | indexes and outputs, safe to delete |
